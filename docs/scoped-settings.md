# 多通道群聊参与设置

0.3.0 将策略与通道传输分开：octop-social-trigger 负责判断、决策模型、频率和限额；octop-channel-octo 继续负责 Octo 连接、收件箱和发送。

## 配置顺序

先设置插件总开关与试运行，再选择配置范围：全局默认 → 通道类型 → 机器人/通道实例 → 群 → 群内专家。后面的范围优先，未修改的项继续继承上级。配置范围下统一说明继承关系，不在每个字段旁重复标注；“恢复继承”只删除当前范围的覆盖。

选择群时先选通道类型，再选机器人，最后选群。群名仅用于显示；后台使用通道类型、实例 ID、群 ID 和专家 ID。名称相同或不同平台使用相同群 ID 不会共享配置。群列表来自已观察到的群会话；没有群时也能编辑默认值。

智能模式显示决策模型开关和提示；仅当开关打开、宿主模型已启用并配置时，展开每天调用上限和等待时间。调用上限独占一行，等待时间放在参与概率右侧；模型关闭时仍保留本地规则需要的相关度门槛与参与概率。每条参与模式保留频率限制。静默时间只在开启时显示。上下文、合并等待和高级限制默认折叠，切换模式保留已有数值。

屏蔽词在主界面仅显示入口和数量，点击后打开管理窗口；同一输入框用于搜索和批量添加，点击添加或回车才加入列表，不把搜索文字自动保存成新词。可通过删除和分页管理，按配置范围整体继承或覆盖；空列表可覆盖上级词表。插件与通道开关开启时，普通消息、@ 消息和命令都会在决策前检查，命中后终止后续通道处理，试运行也生效。群聊临时历史会在进入专家前过滤。此功能只做文本和附件名称的词条匹配，不识别媒体或扫描既有专家会话、持久记忆；需要这些范围时应使用相应的内容审核方案。

## 消息与模型能力

所有已注册的 BaseChannel 通道均使用同一入站钩子。自动参与要求启用群聊策略、明确拥有全部群消息范围、稳定群/发送者 ID、明确 @ 状态和可靠的发送者机器人标记。已启用插件的通道中，未选中群的普通消息以及缺少必要识别信息的群消息会跳过；人工 @ 和命令保留通道原有规则。插件不能凭空获得平台尚未下发的消息。

QQ、Octo、Discord、飞书和 Telegram 提供了相应接入路径。QQ 和 Octo 使用离线真实 Gateway 链路验证；其他适配器的字段、权限和激活策略通过自动化测试验证，实际平台收发仍须在各部署环境验收。Octo 通过已有群成员缓存确认 robot 标记，查询不可用或身份未知时跳过普通消息；不会把未知身份当成人类。Telegram 仍执行账号、群、发送者和命令归属检查。

保留通道原有“仅 @ 回复”作为回退：插件或通道开关关闭时会恢复通道原规则。策略插件在原生激活判断之前观察普通消息，选中后通过宿主授权的续派发接口启动专家。不要为了启用选择性参与而将通道改成每条回复。

决策模型选项默认开启，只有宿主模型已启用并可用时才调用；超时、错误或限额耗尽时回退规则。各群调用共享每日预算，调用前执行原子预占。试运行也可能调用决策服务，但不会启动主专家或发送回复。

## 升级与兼容

配套更新 Fork Octop、Gateway、策略插件；使用 Octo 时还需更新 Octo 通道插件。新版要求 Gateway 的 on_inbound_claimed 交接接口和通用 plugin_group_settings。宿主与插件版本不匹配时给出更新提示。旧 host-patches-0.1.x ZIP 不包含这些能力，新构建仅生成插件包。

schemaVersion=2 使用命名空间化的实例键和明确的群允许范围。第一次保存某群设置才将其纳入范围；修改全局或通道默认不会批量启用新群。v1 配置、群/专家覆盖和允许范围迁移为 QQ 命名空间，不会自动启用 Octo 等新通道。冗余覆盖会移除以恢复继承；原有 QQ 去重、回复配额和未确认预占一并保留。迁移写入前使用配置文件原子替换，不删除状态数据库。

Octo 的策略接管会结束原始被动消息的收件箱交接，避免跳过消息挤满待处理容量。后续选中的回复重新进入正常 started/completed 流程；启动专家后的中断仍标记 uncertain。自动参与是尽力而为的被动回复，不自动重放已由策略消费的群消息。

Octo 收到撤回事件后会记录持久标记并拦截对应消息；策略在评分和派发前检查该标记，从上下文中排除撤回内容。已经发送的回复无法由取消待发任务撤销。
